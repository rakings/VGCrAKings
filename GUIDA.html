Mettere online rAKings VGC

Guida passo per passo, pensata per farla da telefono. Tempo: circa un'ora, quasi tutta attesa.

Cosa serve
  • Lo zip tornei-vgc-sito.zip che ti ho preparato.
  • Un account GitHub (gratuito) e, per le notifiche dentro l'app, uno su OneSignal (gratuito).
  • Un indirizzo email per i contatti e la privacy.

Tocca ogni passo per aprirlo. I nomi dei menu possono cambiare un po' nel tempo.

1Crea l'account GitHub e il deposito del sito
  1. Vai su github.com e tocca Sign up. Scegli un nome utente semplice: finirà nell'indirizzo del sito (nomeutente.github.io).
  2. Conferma l'email, poi tocca il + in alto e New repository.
  3. Nome: esattamente NOMEUTENTE.github.io, con il tuo nome utente (per esempio rakings.github.io). Così il sito sta all'indirizzo semplice e le notifiche funzionano meglio. Lascia Public e spunta Add a README file. Tocca Create repository.

Dal telefono, nel browser apri il menu e scegli Sito desktop: i menu di GitHub, soprattutto Settings, si trovano molto più facilmente.

Il tuo sito avrà questo indirizzo: https://NOMEUTENTE.github.io/

2Carica i file del sito

Prima decomprimi lo zip tornei-vgc-sito.zip (con l'app File del telefono, o sul computer). Hai due strade.

A. Dal computer (consigliata, 5 minuti)

  1. Apri il deposito su GitHub, tocca Add file → Upload files.
  2. Trascina tutto il contenuto della cartella decompressa, compresa la cartella nascosta .github.
  3. In basso tocca Commit changes.

B. Solo dal telefono

  1. Add file → Upload files e seleziona tutti i file della cartella (non le cartelle): index.html, privacy.html, i18n-data.js, sw.js, manifest.webmanifest, manual.json, regionali.json, le immagini (icon-*.png, badge-96.png, favicon-64.png, logo-egg.webp, share-card.jpg) e i quattro programmi update_events.py, update_news.py, make_share_pages.py, send_reminders.py. Poi Commit changes.
  2. La cartella .github non si carica da telefono: crea i due file a mano. Tocca Add file → Create new file, nel nome scrivi .github/workflows/update.yml (le barre creano le cartelle), incolla il testo qui sotto e tocca Commit changes. Poi ripeti per .github/workflows/reminders.yml.

update.yml

name: Aggiorna tornei
on:
  schedule:
    - cron: "0 */3 * * *"
  workflow_dispatch:
permissions:
  contents: write
jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: python3 update_events.py
        env:
          LIMITLESS_KEY: ${{ secrets.LIMITLESS_KEY }}
          NTFY_PREFIX: ${{ vars.NTFY_PREFIX }}
          ONESIGNAL_APP_ID: ${{ vars.ONESIGNAL_APP_ID }}
          ONESIGNAL_API_KEY: ${{ secrets.ONESIGNAL_API_KEY }}
          SITE_URL: ${{ vars.SITE_URL }}
      - run: python3 update_news.py
        continue-on-error: true
        env:
          NEWS_BOT: ${{ vars.NEWS_BOT || '1' }}
      - run: pip install pillow
        continue-on-error: true
      - run: python3 make_share_pages.py
        continue-on-error: true
        env:
          SITE_URL: ${{ vars.SITE_URL }}
      - run: |
          git config user.name "bot"
          git config user.email "bot@users.noreply.github.com"
          git add events.json
          [ -d e ] && git add -A e
          [ -f news.json ] && git add news.json
          [ -f notify_state.json ] && git add notify_state.json
          [ -f news_cache.json ] && git add news_cache.json
          git diff --staged --quiet || (git commit -m "Aggiorna tornei" && git pull --rebase && git push)

3Accendi il sito (GitHub Pages) e i permessi del bot
  1. Nel deposito: Settings → Pages. In Build and deployment scegli Source: Deploy from a branch, ramo main, cartella / (root), poi Save.
  2. Dopo uno o due minuti, nella stessa pagina compare l'indirizzo del sito. Aprilo: dovresti vedere il logo con l'uovo. Gli elenchi saranno vuoti finché il bot non gira.
  3. Settings → Actions → General → Workflow permissions: scegli Read and write permissions e tocca Save. Senza questo il bot non può salvare i dati.

6Notifiche dentro l'app con OneSignal
  1. Vai su onesignal.com, crea un account gratuito e una nuova app di tipo Web.
  2. Come indirizzo del sito inserisci quello del passo 3. Come icona predefinita puoi usare .../icon-192.png.
  3. In Settings → Keys & IDs copia l'App ID e la REST API Key: l'ID va nel sito (passo 4) e nella variabile, la chiave solo nel segreto (passo 5).
  4. Non incollare mai nel sito il codice che OneSignal ti mostra ("Add code to site"): il nostro lo contiene già e due codici insieme si bloccano a vicenda. Serve solo l'App ID.
  5. Apri il sito dal telefono, tocca l'ingranaggio, attiva una categoria e Attiva le notifiche su questo telefono: devi vedere la richiesta di permesso.

iPhone: le notifiche funzionano solo se prima aggiungi il sito alla schermata Home (Safari → Condividi → Aggiungi alla schermata Home).

Non l'ho potuto provare con un account vero, e i siti su GitHub stanno in una sottocartella: se le notifiche non partono, il ripiego è ntfy (variabile NTFY_PREFIX) oppure un indirizzo proprio per il sito.

7Fai partire il bot per la prima volta
  1. Nel deposito apri la scheda Actions, scegli Aggiorna tornei e tocca Run workflow.
  2. Dopo qualche minuto deve diventare verde. Torna nel deposito: devono comparire events.json, news.json, news_cache.json e la cartella e con le pagine di condivisione.
  3. Apri il sito: ora ci sono i tornei. La lettura delle news è parziale al primo giro e si completa nei giri successivi (ogni 3 ore).

Il bot è stato provato su pagine simulate, non sui siti veri. Se un passaggio diventa rosso, tocca il nome del lavoro e leggi l'ultima riga del registro: se mi mandi quel testo lo sistemo.

Il primo giro non manda notifiche, per non travolgere nessuno con i tornei già esistenti.

8Controllo finale, da fare sul telefono

Prima di tutto: apri https://NOMEUTENTE.github.io/diagnostica.html. Controlla da sola cosa funziona e cosa manca (dati dei tornei, notifiche, file, errori nel codice) con righe verdi, gialle e rosse: non serve la console del browser. Il pulsante Pulisci toglie le registrazioni vecchie rimaste nel browser dopo aver rifatto il deposito.

  • Il sito si apre e si vede il logo.
  • Cambia lingua da ingranaggio → Lingua.
  • I filtri e il calendario funzionano.
  • Tocca Installa (Android: menu del browser → Installa app) e apri l'app dall'icona.
  • Tocca il tasto Condividi su un torneo e mandalo a un amico: controlla l'anteprima in WhatsApp e Telegram.
  • Attiva una notifica e controlla che il permesso venga chiesto.
  • Prova il modulo della top 8: compila un posto, anche solo con il codice del rental team, e tocca Prepara la scheda.
  • Google Calendar e Apple / Outlook su un torneo con data.

Le anteprime di WhatsApp e Telegram vengono conservate per un po': se cambi qualcosa e non vedi la novità, aspetta o prova con un altro torneo.

9Prima di far girare la voce
  • Scrivi a Limitless (contact@limitlesstcg.com) per chiedere il permesso di usare i loro risultati: la bozza è nella nostra conversazione. Se rispondono di no, metti NEWS_BOT a 0.
  • Privacy: compila privacy.html con nome ed email, e fai controllare il testo se puoi.
  • Disclaimer: in fondo alla pagina c'è già l'avviso che il progetto non è affiliato a Nintendo, Game Freak, Creatures o The Pokémon Company.
  • Donazioni: sono un reddito. Tienile presenti per le tasse e per l'eventuale autorizzazione di chi lavora nel pubblico.
  • Locali: decidi dove ricevere i moduli (CONTACT_EMAIL) e controlla ogni segnalazione prima di inserirla.
10Come aggiornare il sito in futuro
  1. Mi dici cosa cambiare e ti preparo lo zip nuovo (se apri una nuova conversazione, carica il tuo index.html attuale).
  2. Carica solo i file cambiati, di solito index.html e gli script. Non sovrascrivere i file che il bot riempie da solo: events.json, news.json, news_cache.json, notify_state.json, reminder_state.json e la cartella e.
  3. Dopo aver caricato index.html, rimetti gli indirizzi del passo 4, o dimmeli e li lascio già scritti.

Aggiunte a mano: un torneo che il bot non trova (per esempio una Global Challenge) va in manual.json; i Regionali e gli eventi ufficiali sono in regionali.json. Basta copiare una voce esistente.
